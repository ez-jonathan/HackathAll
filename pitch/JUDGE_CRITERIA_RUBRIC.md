# ⚖️ Hackathon Judge Evaluation Checklist

Score your project before the judges do. Target ≥90% readiness.

---

### 1. Technical Execution (25%)
- [ ] **Working Demo**: Does the core flow actually execute without error during evaluation?
- [ ] **Sponsor API Depth**: Did you use the sponsor tools meaningfully rather than cosmetic wrapping?
- [ ] **Resilience**: Is there an automatic fallback if an API endpoint hits rate limits?
- [ ] **Clean Code**: Zero exposed keys in repository, reproducible build (`npm run build`).

### 2. Originality & Innovation (25%)
- [ ] **Aha! Factor**: Does the product make the judge pause and say, "I didn't think of that"?
- [ ] **Novel Composition**: Does it combine multiple technologies in an unexpected way?
- [ ] **Agentic Independence**: If using AI agents, do they perform authentic work with verification?

### 3. Design & User Experience (25%)
- [ ] **Aesthetic Polish**: Modern dark UI with consistent typography, badges, and spacing.
- [ ] **Zero Confusion**: Is the immediate next action on the page obvious within 2 seconds?
- [ ] **Feedback States**: Are there skeleton animations on load and toast confirmations on action?
- [ ] **1-Click Judge Mode**: Can a judge test the product without signing up or creating an API key?

### 4. Business Impact & Practicality (25%)
- [ ] **Real Problem**: Does this solve a genuine pain point for a defined user base?
- [ ] **Clear Pitch**: Can the team articulate the problem and solution in under 45 seconds?
- [ ] **Post-Hackathon Feasibility**: Could this reasonably become a real startup or open-source tool?
